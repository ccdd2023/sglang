1 TL;DR — 之前的解读有重大缺陷

🎯 核心发现：FAIL_acc 不是"准确度"，是"模型走默认 FAIL 模板的频率"

人工 spot-check 揭示：R19 的 60% FAIL_acc 不是"识别 bug 60%"，而是"模型倾向写 hallucinated FAIL reason"。 R27 的 0% 不是"模型保守"，而是"模型完全 robotic 不分析（输出 13 字符模板）"。 R26 的 27% 介于两者之间。

⚠️ 之前 Lossy doesn't degrade accuracy 的 claim 需要 reframe

R19 lossy 60% vs lossless 52% —— lossy 看起来提升 FAIL detection，但 reasoning 都是 boilerplate。 "8% UNK 提升到 20% UNK"（R26）—— lossy 真的引入 c-code-leakage 失败模式。 差异在噪声内，"不降低" ≠ "等价"。

⚠️ 之前"Lossy doesn't degrade accuracy"是 over-claim

事实：R19 lossy 60% vs lossless 52% 在 ±10pp 的噪声范围内，无法判定"提升"或"等价"。 R26 lossy 引入 20% UNK（其中 c-leak 是 lossy 直接造成的），是 lossy 的真实代价。 更准确的表述："Lossy 引入新的失败模式（UNK、c-leak），但不显著改变 model 对 PASS/FAIL 的倾向；总体 verdict 分布仍在 lossless ±15pp 范围内"。

之前未发现的真相

  • R27 = 完全 robotic，不是"保守" —— 13 字符输出 = 0 reasoning
  • R19 "60% FAIL_acc" 主要是 hallucinated —— 5/5 agent 给出不同的 plausible-sounding 但都不是从代码读出的
  • R26 lossy 引入 c-leak —— 模型进入 Python AST 节点 walk 模式
  • 3B-Coder 在 lossless 下也不分析，不是 lossy 的副作用

6 方法论修正建议

不可信的 claim（应撤回或重新表述）

之前说法问题重新表述
"R19 60% FAIL_acc 是 best" 60% 主要是 hallucinated default FAIL template R19 倾向 FAIL 但 reason 是 boilerplate；不是真"识别 bug"
"R27 0% FAIL_acc 是 worst" 0% 是因为模型根本没分析（13 字符模板复读） R27 在 verdict 任务上无推理能力，不是"过度保守"
"Lossy doesn't degrade accuracy" 差异在 ±10pp 噪声内，且 lossy 引入了 UNK / c-leak 失败模式 "Lossy 不显著改变 PASS/FAIL 分布，但引入 UNK 失败模式（R19 0%→R26 20%）"
"R26 27% 介于 R19 60% 和 R27 0% 之间" 数字看似线性，但 reasoning 质量不同 R26 是"弱 reasoning"，R19 是"幻觉 reasoning"，R27 是"无 reasoning"

应该补的实验

  1. 人工评分 reasoning 质量：3 个 reviewer 独立判断每个输出的"reason 与代码真实 issue 的对应程度"，1-5 分
  2. 加 PASS 子集 ground truth：从 SWE-Smith manifest 找 5 个"未 mutate"的 case 做 negative control
  3. 加 random/empty baseline：prompt 去掉 code 看模型默认行为
  4. 看 reasoning 而不是 verdict：用 sentence-BERT 计算 model reasoning 与 manifest patch description 的相似度
  5. 抽样 ≥30 case：当前 n=15 置信区间太宽（±22pp），差异都在噪声内

结论对原报告的影响

Speed-accuracy trade-off 的真实情况

之前的"决策矩阵"（speed first → R26, accuracy first → R19, avoid → R27）框架还在， 但 "accuracy" 的实际含义不是"识别 bug"，而是"模型写得像在分析的程度"。 R19 看起来"最准"，但写的是 boilerplate；R27 看起来"最不准"，但实际是 0 reasoning。 三个 config 的真正区别是 reasoning 强度，不是 verdict 准确度。
