🔬 第一层：Accuracy 相关实验

方法是否安全、数值正确、输出一致？

安全性 E3/E4：Exact-Content Gate Safety

实验设置

数据集： 从 SWE-bench Verified 500-case manifest 中抽取 550 对 near-match 负样本
构造方式： 保持相同 repo/path/function 定位器，仅修改字面量、运算符、函数调用、变量名、注释或函数体
策略： 仅使用 exact_content_gate（内容 SHA256 签名完全匹配）
评估指标： False Accepts（错误允许复用）、False Rejects（错误拒绝复用）
MetricValue结论
False Accepts0 / 550✅ 安全
False Rejects0 / 550✅ 无漏判
Exact-content hits50 / 50正样本全部命中
设计原则：AST、span、path 仅作为 locator（定位器），不参与 reuse 判定。只有 exact-content signature（SHA256 哈希）完全匹配才允许 KV 复用。这确保了即使代码结构相同、仅一个运算符改变，也会被正确拒绝。

数值正确性 E5：RoPE Delta Alignment

实验设置

模型： Qwen2.5-7B-Instruct
测试方式： 对同一 code segment 在不同 prompt 位置进行 KV reuse，比较 reused KV 与 fresh compute 的 key 向量余弦相似度和 next-token 分布
变体： (a) Correct Δ — 计算正确 RoPE 位置偏移；(b) No Rotation — 不做 RoPE 旋转；(c) Wrong Δ — 故意使用错误偏移
评估指标： Mean K Cosine, Top-1 Agreement, KL Divergence
VariantMean K CosineTop-1 AgreementKL Divergence结论
Correct Δ0.99996.9%0.0147✅ 数值一致
No Rotation0.966——降级
Wrong Δ (≥16)0.950——错误
解释：0.999 K cosine 表示 reused KV 与 fresh compute 的 key 向量几乎相同；0.0147 KL divergence 表示 next-token 分布差异极小；96.9% top-1 agreement 表示下一 token 选择高度一致。

🔍 E8 消融实验：机制拆解

实验设置

模型： Qwen2.5-7B-Instruct
数据集： SWE-bench Verified 500-case manifest（复用 E6 同一批 cases，避免数据集漂移）
Case 数： 20 cases
Bucket： 32000 chars（注：受 GPU 容量限制，此 bucket 下 ablation 效果未充分展现）
max_tokens： 32（输出一致性 sanity setting）
4 Ablation Modes：
  (a) ablation_prefix_only — 纯 prefix cache baseline
  (b) ablation_hints_no_exact — code hints only, reuse_mode=lossless（禁止 exact match）
  (c) ablation_exact_no_hints — anchor spans + exact match，无 next_agent_prefix 调度
  (d) ablation_exact_gate_rope — anchor spans + exact match + RoPE delta（完整路径）
评估： TTFT speedup vs prefix-only, cached-token gain, exact hit rate, output F1
ModeP50 TTFTSpeedupCached GainExact HitsOutput F1
Prefix only4156ms1.00×—0/201.000

⚠️ 32k bucket 下的 Ablation 受限：E8 当前在 32k bucket 运行，受 RTX 4090 24GB 限制，planner+implementer KV 无法同时驻留，所有 mode 的 cached_tokens ≈ baseline。Ablation 未能展示预期差异。需在 16k bucket 重跑 E8 以获得有效的机制拆解结果。
仍可读的结论：hints only mode 的 F1=0.604（低于 prefix_only 的 1.0），说明 hints 改变了输出但不加速 prefill；exact gate mode 命中 13/20 但无实际 KV 复用（GPU 容量限制）。

📋 诚实局限性

  1. GPU 容量瓶颈：RTX 4090 24GB 只能容纳 ~31k tokens KV cache。32k+ bucket 的 planner+implementer 无法同时驻留 → exact_hit 报告成功但 cached_tokens=0。
  2. E6 speedup 未达目标：目标 1.3×，实际 1.16×（16k, 50-case）。10-case 校准曾达 1.56×，差异来自样本多样性。
  3. E8 ablation 不完整：32k bucket 下无法有效隔离各子系统贡献，需 16k 重跑。
  4. E2E speedup modest：100-case E2E 仅 1.02×，但这是 realistic workload 的预期行为（decode/HTTP 噪声稀释 prefill savings）。
  5. HiCache file backend leak：文件存储后端存在内存泄漏，未作为主线使用。
