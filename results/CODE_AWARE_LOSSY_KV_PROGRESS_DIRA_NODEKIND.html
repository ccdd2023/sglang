(2) Direction A 假设 · interface 敏感、body 安全

核心假设

一个函数的 interface（signature + docstring）是跨上下文敏感区：callers 依赖它；它位于 chunk-prefix 边界，正是 HKVD 偏差最高的位置（slide 8 实测 pos1 K 偏差 +7.2%）。而 body 是 byte-stable 的实现细节，安全 copy。

推论：recompute 到每个 chunk 的真实 interface 边界（而非均匀 frac × chunk_len）应在更低 recompute 成本恢复精度 -> 等预算 B 下 node-kind ≥ R32 type_match。

判决判据

结果含义
per-chunk 自适应边界 > uniform frac @ equal Bcode structure 买精度 -> Direction A confirmed，补 novelty 缺口
per-chunk 自适应边界 ≤ uniform frac @ equal Bcontiguous form 证伪 -> FALSIFICATION，回 slide 18 选 B/C

关键设计：等预算 B 是核心。R34 没控预算 -> 效果被归为「全局 FRAC bump」。本 deck 固定 B 比 accuracy，才能区分「code structure 买精度」vs「只是多算了」。

(3) 连续性约束 · 为什么 scattered 不可行 -> contiguous

slide 18 的完整 Direction A 需要非连续 recompute

「recompute signature + scattered 控制流 token，copy docstring + boilerplate」-> 控制流在 body 中段，recompute 的 token 不连续。

sglang prefill 强制 contiguous cached prefix

radix_cache.py:2432-2437：非连续 copy 膨胀 device_indices 超过 input_len -> 负 num_extend -> flashinfer crash。prefill 把 device_indices 当作连续前缀处理。

scattered 的代价 -> 对 TTFT 论文自毁

scattered recompute 需多轮 gap staging（recompute_gap_chunk），每轮 prefill 吃 TTFT。现有 2 轮 inter-chunk gap-prefill 仍达 1.38×，但许多 intra-chunk 控制流 gap 不会。

落地：contiguous interface-recompute

recompute  [chunk_start, interface_end)   # 签名 + docstring，连续头部
copy       [interface_end, chunk_end)   # body，整段 copy + RoPE

契合现有 head-recompute executor（无需改 kernel），每个 function/class chunk 都触发，是「code structure 决定 recompute 边界」的干净（但较弱）测试。强 scattered form 因 TTFT 不可行被排除（§附录）。

(5) 副产品 · byte_to_tok 静默 None bug 修复（pre-existing）

症状：_build_byte_to_token_map 运行时静默返回 None

# radix_cache.py · 修复前
def _build_byte_to_token_map(text, tokenizer):
    offsets = tokenizer(text, return_offsets_mapping=True)["offset_mapping"]  # HF Encoding 对象
    for (_st, en) in offsets:        # <- ValueError: too many values to unpack
        ...
    except Exception:  # bare except 吞掉
        return None                  # 静默 None

根因 + 后果

  • sglang 的 get_tokenizer 返回 raw HF Qwen2Tokenizer；return_offsets_mapping=True 返回 BatchEncoding of tokenizers.Encoding 对象 -> tuple unpack raise -> bare except 吞掉。
  • 后果：R32/R38b 一直走 O(chunks×text) per-chunk re-encode fallback。这掩盖了 bug — R32 仍工作（fallback 给出正确 offset），只是慢。

修复 + 验证

if offsets:
    _first = offsets[0]
    if hasattr(_first, "offsets"):   # 解包 Encoding 对象
        offsets = list(_first.offsets)

验证：chunk-start 边界上 bisect_right(ends, byte) == len(encode(text[:byte]))，0/120 偏差 -> R32/R38b 的 offset/accuracy 不变，仅更快（R32 745→715ms）。这个 fix 也是 node-kind 能触发的前提 — 它需要 map；否则静默退回 frac = R34 no-op 陷阱。

关键：这是 pre-existing bug，被本次工作 uncover。memory: byte-to-tok-broken-encoding-fix-2026-07-10。

(13) 机制解读 · 假设被推翻（body 比 docstring 更关键）

原假设

interface（signature + docstring）是跨上下文敏感区，body 是 byte-stable 实现细节、安全 copy -> recompute interface、copy body 应在等预算下胜出。

数据暗示相反

body（R32 uniform head 重算的部分）比 docstring（nodekind 重算的部分）更精度关键。

  • R32 重算「前 K token」（= signature + 部分 body），把 copy 损失恢复到曲线。
  • nodekind 重算到 interface_end（= signature + docstring），把 body 全部 copy -> body 的 stale KV 没被重算 -> 精度落在曲线下方。
  • nodekind_sig（只重算 signature，连 docstring 都 copy）更差（3.3%）-> copy 得越多越差，进一步印证 body 敏感。

结论

position-driven head recompute（R32）beats code-structure-driven interface recompute at equal B。code structure（node-kind）不买精度。这强化 CLAUDE.md §2a：method 是 speed optimization（Pareto trade），非 accuracy-preserving；code-structure-driven recompute selection 不胜 position-driven。

与上一份 deck 的诊断一致：accuracy 杠杆 = 位置（FRAC），代码结构只驱动 chunking（速度）。Direction A 未能打破这个分工。
