4-Layer cache architecture

Each layer adds a reuse mode on top of the previous. Speedup numbers are cumulative (multiplicative against a fresh-allocator baseline).

LayerMechanismCumulative speedupStatusEvidence
L1 Prefix cache (token-id radix) 1.20× production SGLang upstream feature, baseline of all 4 layers
L2 Whole-slot byte-exact (loose fuzzy match) 1.31× production giant_pandas_50_l3_off REPORT.md
L3 Placeholder MiniLM k-NN body 1.65× DEPRECATED 8.2% non-byte-identical pool hits (variable rename / whitespace drift). Default SGLANG_PLACEHOLDER_KNN_MATCH=0
L4 AST chunk pool (byte-exact per chunk) ~1.49× (predicted) CURRENT TARGET Direction #3 Phase A/B/C/D landed; 5-task smoke pending

Why we lost the 0.34× gap (1.65× → 1.49×) by deprecating L3: the gap was never safe. L3 silently accepts variable renames, comment edits, and signature changes whenever cos ≥ 0.85. On the giant-codebase 50-task run, 8.2% of pool hits were non-byte-identical. We recovered as much of the safe L3 contribution as we can via byte-exact L4, accepting a smaller but production-safe speedup.

match_prefix decision flow

The composition chain that runs on every request. L3 is crossed out because it is OFF by default in production; L4 is the new opt-in layer.

# match_prefix call chain (simplified) req → _match_prefix_helper(key) ├── _try_lossy_fuzzy_match # L1+L2 (byte-exact slot reuse) │ returns (value, last_node) │ ├── _try_placeholder_knn_lossy_match # L3 (DEPRECATED, off by default) │ SGLANG_PLACEHOLDER_KNN_MATCH=0 │ ├── _try_placeholder_chunk_lossy_match # L4 (NEW, opt-in) │ ├── _build_chunk_plan(spans) │ │    → list[ChunkDecision] (copy_pool | dense_prefill) │ ├── _find_byte_exact_chunk_entry(chunk, entries) │ │ # strict: byte_start + byte_end + token_ids must match │ └── _execute_chunk_plan(plan) │    → alloc + move_kv + apply_rope_delta_to_head │ └── return (value, last_node) # extended value list drives prefill

Byte-exact is binary. If byte_start + byte_end + token_ids don't all match exactly, the chunk falls back to dense prefill and bumps a skip_byte_drift counter. There is no cos ≥ 0.85 fallback. This is the safety contract that L3 broke.

How to enable / disable

Production default (L1+L2 only, L4 OFF)

# Nothing to set. SGLANG_CHUNKED_PLACEHOLDER_KNN defaults to 0.
python -m sglang.launch_server --model Qwen/Qwen2.5-3B-Instruct

Research mode (L4 chunk pool ON, for validation)

export SGLANG_CHUNKED_PLACEHOLDER_KNN=1
export SGLANG_CHUNKED_PLACEHOLDER_KNN_MATCH=1
python -m sglang.launch_server --model Qwen/Qwen2.5-3B-Instruct

Giant-codebase 5-task smoke (P0)

python benchmark/multi_workflow/bench_giant_codebase_reuse.py \
    --manifest  results/giant_codebase/tasks/pandas_50.jsonl \
    --repo-root results/giant_codebase/pandas_src \
    --out-dir   results/giant_codebase/runs/giant_pandas_5_l4_on_$(date -u +%Y%m%d_%H%M%S) \
    --model     Qwen/Qwen2.5-3B-Instruct \
    --max-tasks 5 --agent-count 5 \
    --mode      placeholder_knn_reuse --segment-count 5 \
    --no-vary-code

Note: for any run with > 3 tasks you MUST also add --force-evict --disable-overlap-schedule --max-running-requests 1 to avoid the _delete_leaf assertion. See memory: _delete-leaf-bug-2026-06-24.
