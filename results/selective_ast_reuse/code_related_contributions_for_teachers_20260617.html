先用最朴素的话解释

老师不需要先懂 SGLang、KVCOMM 或 AST。只要记住：长代码 prompt 的 prefill 很贵，而代码片段经常在多轮 agent workflow 中重复出现。

Problem

代码 prompt 太长

修 bug 时，LLM 往往要读 issue、tests、整份源码文件。模型生成第一个 token 前，要先为这些 token 计算 KV cache，TTFT 会变长。

Opportunity

代码片段会重复

Planner、Coder、Reviewer 之间经常读同一段函数、方法、导入、文件前缀或相关依赖代码。重复计算这些 token 的 KV 是浪费。

Our Answer

只复用可证明相同的代码 KV

我们不复用模型答案，也不凭 AST 名字猜测复用；只有代码内容签名精确匹配，并通过风险门控，才复用对应 KV。

这些贡献不是彼此孤立的功能，而是一条从 runtime 到算法、再到实验可信度的链路。

AgentTemplateKV prompt layout

把 code_base 放在稳定、靠前、规范化的位置，让多 agent 请求之间更容易出现可复用的 exact code anchors。

2

Runtime exact-anchor path

Planner 结束后可保护 exact-content code anchors；后续 Implementer/Reviewer 带同一 hint 时能命中 device KV。

3

AST granularity study

验证 AST 结构本身不是安全复用充分条件；AST 应该做 locator，真正安全门是 content signature 和 distance gate。

4

Selective code reuse

从 simple function/method 扩展到 function/method/control_block/file_prefix，并加入 predicted-d guard。

5

Graph-aware selection

把目标 symbol 的调用/导入邻域映射回 prompt 中已有 AST spans，让复用选择从语法局部走向程序依赖相关。

我们的设计里有一个很重要的边界：客户端选择候选，服务端决定是否真的复用。

三代 code selection 的区别

这部分是老师最容易问的：到底“复用哪些代码”是怎么变的？

Simple AST · 上周 baseline

只看 function / method

优点是保守、安全；问题是命中有限，很多稳定的大块上下文，例如文件前缀、控制块，无法被复用。

functionmethod
Extended AST · 本周主方法

加入控制块和文件前缀

基于 granularity sensitivity 统计，只扩展到低风险粒度：function, method, control_block, file_prefix。

functionmethodcontrol_blockfile_prefix
Graph-aware · 新接入

按程序依赖关系选代码

围绕目标 symbol 选择 direct callees 和 import/call neighborhood，再映射回 whole-file prompt 中已有 AST spans。

target symbolcalleeimport neighborhood
核心区别：simple/extended AST 是语法局部选择；graph-aware 是程序关系选择。无论哪种选择，最终都必须经过 exact content signature，不能仅凭“长得像”复用。

安全性：为什么不是乱复用？

这里可以回应两个常见质疑：AST 名字相同是否足够？阈值是否拍脑袋？

我们发现 AST 结构不是充分证据

AST × KV-distance 分析显示：within-AST-type 的平均 normalized distance 是 1.6098，cross-AST-type 是 1.3334。也就是说，“同一种 AST 类型”并不天然更近。

实验可信度贡献：修正旧结论

这部分对老师很重要：我们不仅做了方法，也发现并修复了会误导结论的 benchmark 问题。

Bug found

Shared cache contamination

旧 Phase 2 中不同 modes 共用 cache，后跑的 mode 可能复用前一个 mode 留下的 KV，导致结论不可引用。

Fix

Per-mode flush + warmup

每个 mode 独立 flush cache，再进行该 mode 自己的 warmup，避免 mode order contamination。

Fix

Streaming F1 修复

修复 streaming output reader，避免从空 final chunk 计算 F1；skip rows 从 F1 平均中剔除并单独披露。

给老师的 5 句话总结

如果展示时间很短，可以只讲这 5 句。

  1. 我们的目标不是复用模型答案，而是复用长代码 prompt 中重复代码 token 的 KV cache。
  2. AST / graph 只负责定位候选代码片段；真正决定是否复用的是 exact content signature 和 predicted-d safety gate。
  3. 相比上周 simple AST，本周 extended AST 增加了 control_block 和 file_prefix，在 corrected 28-case 上 TTFT 从 580.6ms 降到 45.0ms，executed rows F1 保持 1.0000。
  4. Graph-aware 已经接入同一个 selective driver：24/28 covered，TTFT 38.9ms，F1 1.0000；它选择的是目标代码的调用/导入邻域。
  5. 我们还修复了实验可信度问题：mode isolation、streaming F1、skip-row accounting，使当前结果可以被解释和复现。
