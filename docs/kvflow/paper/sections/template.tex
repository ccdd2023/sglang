\section{M0: File-Module Admit Compiler}
\label{sec:template}

\subsection{Natural modules, not synthesized DAGs}

The reusable objects are file modules already present in the agent
protocol: roles read files, edit, test, and review under a rolling-6
history. We do \emph{not} ask an LLM to invent a new DAG per task, and
we do not treat planner-generated nodes as KV objects.
Figure~\ref{fig:dag-example} is that role graph. The compiler is an
offline oracle on frozen trajectories: it reconstructs each target
prompt, locates \texttt{repository\_code} spans, and keeps only islands
that pass the eligibility gate (Figure~\ref{fig:template-process}).
It is not an online serving policy. Job 137185 uses this
offline oracle so every island has a known $\Delta$ before copy.

\subsection{Serving-class prior}

Users do not share GitHub issues or file bytes. The reusable object at
serving time is a \emph{task class} (rolling-6 coding agent versus
general), not a per-issue PLAN. An offline Beta prior over that class
(coding-agent $\alpha{=}116$, $\beta{=}93$ from 207 expanded24 sources)
admits a source that already passed the protocol gates when later-roles
are positive. The source stores $K$ unrotated. The target locates each
leased span by unique token identity, computes $\Delta$, and rotates $K$
at copy; a non-unique span is Dense. Bind outcomes fine-tune the same
class bin with a damped step so one replay cannot overwrite the prior.
This path is default-off in Table~\ref{tab:eval-summary}: the headline
copy kernel still consumes the offline-oracle PLAN.

\subsection{Eligibility gate}

A span becomes a copy island only if every condition holds:

\begin{enumerate}[leftmargin=1.2em,itemsep=0.2em]
    \item It is a single-file \texttt{repository\_code} module (one path).
    \item The content version is valid for that path in the trajectory
          (no stale-file copy after a later edit).
    \item Source and target token IDs are identical on the span.
    \item The logical shift $\Delta = t_{\mathrm{start}} - s_{\mathrm{start}}$
          is nonzero. Zero-shift copies are dropped so the experiment
          cannot collapse to prefix reuse.
\end{enumerate}

Algorithm~\ref{algo:template-synthesis} is this compiler.

\begin{algorithm}[ht]
\SetAlFnt{\footnotesize}
\DontPrintSemicolon
\KwIn{Frozen trajectories $\mathcal{T}$, tokenizer}
\KwOut{Target groups with true-lossy file islands}
\BlankLine
\Begin{
    $plan \leftarrow \emptyset$\;
    \For{each target prompt $P$ reconstructed from $\mathcal{T}$}{
        $islands \leftarrow$ file modules of $P$\;
        \For{each candidate island $I$}{
            \If{$I$ is not single-file \texttt{repository\_code}}{
                \textbf{continue}\;
            }
            \If{path version of $I$ is stale}{
                \textbf{continue}\;
            }
            \If{token IDs$(I)$ do not match a source span $S$}{
                \textbf{continue}\;
            }
            $\Delta \leftarrow I.\mathrm{start} - S.\mathrm{start}$\;
            \If{$\Delta = 0$}{
                drop $I$ \tcp*{not true lossy}
            }
            \Else{
                attach $I$ with source-side pre-rotate $\Delta$\;
            }
        }
        \If{$P$ has at least one attached island}{
            $plan \leftarrow plan \cup \{P\}$\;
        }
    }
    \Return $plan$
}
\caption{Compile true-lossy file-module islands}
\label{algo:template-synthesis}
\end{algorithm}

On the frozen SWE-bench Verified traces this compiler yields 235 target
groups and 421 islands, after dropping 48 zero-shift islands. Groups
carry one, two, or three islands (89 / 106 / 40). Mean copied tokens
per group are $1{,}537$ against a mean target prompt of $4{,}433$ tokens
(median $4{,}239$; p90 $6{,}759$; max $8{,}721$). About one third of each
target prompt is eligible true-lossy file content; the rest stays Dense.

\subsection{What is stored, and how it is used}

M0 is not a KV cache. The eval PLAN stores eligible islands
$(s,t,L,\Delta)$; it does not allocate $K/V$. In the headline campaign
the source request Dense-prefills, and the controller stores only
admitted islands under $(\textit{source-prefix hash}, \textit{content hash},
\Delta)$ with $K$ already rotated (Section~\ref{sec:kv-management}).
The target request Dense-computes the prefix, copies each leased island
into the target slots, Dense-computes the remainder, and decodes one
token. Ineligible tokens---issue text, tool logs, stale files---never
enter that store. Path and version metadata only locate the span;
token-ID equality is the admit rule. The compiler does not estimate
Attention and does not recompute KV distance online. Prefetch of those
same spans (M3) uses later-roles in the coding protocol, not remaining
target uses, and is off in the headline campaign.
