**成因（git 层精确定位）**：
- `3c1a0e13f`（re-consolidate）时 `RESULT_MANIFEST.json` 为 **76** 条 → summary 写入 76 与 `072fedd7…`；

- summary 此后未再生成 → 该块永久陈旧。

**这不是排序失误，而是设计上的循环**：
`summary ⊃ sha256(RESULT_MANIFEST)`，而 `RESULT_MANIFEST ⊃ sha256(summary)`（已确认 summary 是 RESULT_MANIFEST 的一条 entry，记录值 `70361d74…`）。二者互为输入，**不存在不动点**，无论以何顺序重跑都无法同时自洽。

**影响**：
1. 发布产物对外做出一条**可机器验证且为假**的 provenance 断言；
2. 破坏了 review #1 确认过的**逐字节可复现**性质 —— 我本轮 in-memory 重跑得到 `721c3033…`，与盘上 `e2deec5a…` 不同，**差异恰为且仅为**上述 2 个叶子 + 派生自哈希（22 个 compact **全部逐字节相同**）；
3. 讽刺地由闭合 CP2-12 的修复引入。

**修复（offline，无 GPU）**：
- 从 `provenance.result_manifest` 移除 `file_sha256`（保留 `path` + `authority`），并把 `entry_count` 改为由 consolidator 自身的文件清单推导的 *expected* 条数，或一并移除 —— 打破循环；

## 7. 最终结论（修复 NEW-P1 后即可发布的文本）

1. **Engineering: VALID.** 22 个已授权 primary start 全部通过 hash/provenance/reset/inactive 校验；wave-0 S0 的 40 次 approximate 失败经一次定向 evidence correction 补齐了 plan §5.8 强制的 exclusive terminal reason，全部为 direct `unsupported ← store_miss`。全 Phase 7 未观察到任何自然 cross-store reservation failure。
2. **Mechanism (A8 R0 ceiling): NEGATIVE.** chunk4096 下四个 restart-0 setting 的 paired-target request-path median 为 `0.7723 / 0.7751 / 0.9334 / 0.9362`（R0 比 dense 慢 6–23%，方向与 +5% MDE 相反）；N=8 full-setup 摊销为 `0.6086 / 0.6101 / 0.6398 / 0.6419`，`break_even_observed_N` 全部 `>8/not_observed`。**不发布任何机制固有 speedup headline。** 每 setting 仅 **1 个进程级 replicate**；ES-R0-MDE 正确跳过 8 个 supplement，故预注册的三点区间不可得。
3. **chunk1024 sensitivity 为 chunk-coupled，非 headline.** restart 中位 request-path `1.7370`、N=8 full-setup `1.1890`，对同 body/rho 的 chunk4096 值（`0.9362` / `0.6419`）呈约 1.85× 摆动，归因于 `chunked_prefill_size`/`max_prefill_tokens` 的耦合变更，而非恢复机制本身。
4. **System behaviour (W, S4 vs S0): INCONCLUSIVE / DESCRIPTIVE.** 三个独立 restart 的中位数：rho=1.5 时 all-reusable `1.0021`、workflow-only `1.0276`、miss delta（all/workflow）`−14 / −10`、R0 peak 比 `1.0112`；rho=2.0 时 `1.0250`、`1.0442`、`+2 / −10`、`0.9981`。**不选 winner、不发布任何 scheduler 性能 claim。** A8 NEGATIVE 后，W 的 primary 轴为 cross-store victim/footprint accounting，延迟视图为次要描述性证据。
5. **R4-like 为 synthetic 5x footprint proxy，不执行 KVCOMM.** S0 两个 repeat 均完成 61 请求（`available`/`valid`），但仅 **12/122（9.8%）** 为真实 approximate recovery，**110/122（90.2%）** 为 dense fallback（`unsupported`）；S4 两个 repeat 均注册失败（`diagnostic_unavailable`/`inconclusive`）。性能排名禁用。

## 8. 最终 caveats（必须与结论同时出现）

1. `practical=NONE` 限定于本模型、合成 prompt 族、exact-output 不变量、本 GPU 与 `chunk=1024`，非普遍不可行性 claim。
2. R0 是 ceiling 路径，非被提升的 practical 候选。
3. R2 为 `disabled_not_comparable` 且未执行；Phase 4 chunk1024 的 R2 数值**不得**与 Phase 7 chunk4096 结果同表排名或合并统计。
4. `r2_like` 是 2x synthetic representation-multiplicity footprint profile，非 R2 执行；`R4-like-5x` 是 synthetic footprint proxy，非 KVCOMM。
5. P6-F 只证明 fault-injected fallback。**自然压力下的 fallback 可达性仍未证明**：两个 wave-0 cell 均为 `fallback_reachability {passed: false, rounds: 0}`，且 22 个 start 中零次自然 reservation failure。
6. wave-0 的 "reachable" 仅指 profile **注册成功且该轮通过 validity/reset 校验**，**不代表 approximate recovery 成功**。S0 在四个 approximate profile、两个 formal repeat 中均为 `approximate_gpu_recovery = 0` / `dense_fallback = 5`（合计 40，全部 `unsupported ← store_miss`），这正是其 cell 为 `diagnostic_unavailable`、artifact 为 `inconclusive` 的原因；S4 在四个非 R4 profile 上为 5/5 恢复。
